# Skill Creator：创建 Skill 的 Skill

把重复性工作流变成一个结构清晰、轻量、可直接使用的 Agent Skill 包。核心信念：**先想清楚再动手，能轻则轻，结构为复用服务**。

## 总流程（6 步）

```
① 意图对话 → ② 定边界与形态 → ③ 参考扫描 → ④ 写 SKILL.md（先 description 后正文）
→ ⑤ 补必要资产 → ⑥ 自检交付
```

## Step 1：意图对话（先理解，再生成）

动手前，只问会改变设计的问题，问清这六件事：

1. **核心任务**：它以后要稳稳接住哪一类重复工作？
2. **真实输入**：用户实际会丢给它什么材料（文档/代码/链接/口语描述）？
3. **成品输出**：做好后必须交回什么？格式是什么？
4. **明确不做**：哪些相近的事情它不负责？
5. **成功标准**：怎么算"做好了"（速度？一致性？可审计？风格？）
6. **已有资产**：有没有现成的文档、脚本、模板、例子可以直接利用？

对话纪律：

- 像坐在旁边的共创伙伴，不像表单收集员。先邀请用户自然描述，小模板只在对方要求时提供。
- 非核心缺口直接用**写出来的假设**补齐并告知用户，不为小事打断。
- 每轮最多问 1 个核心分叉问题，最多 2 轮；再不清楚就按最合理推断继续，并标注 `假设`。
- 能用一句话说清这个 skill 干什么时，停止提问。
- 镜像用户的语言；中文语境下语气柔和、陪伴式。

产出物：一句能力描述 + 输入清单 + 输出清单 + 不做清单 + 推荐形态。

## Step 2：定边界与形态

**边界四问**（每个 skill 必须能回答）：

- 拥有什么重复任务？
- 产出什么输出？
- 哪些相近请求不属于它？
- 哪些细节不该塞进 `SKILL.md`？

**形态按复用程度选最轻的一档**：

| 形态 | 适用 | 交付物 |
| --- | --- | --- |
| 轻量版 | 个人用、探索性、复用未证实 | 只写一个 `SKILL.md` |
| 标准版 | 团队复用、有固定流程 | `SKILL.md` + 少量 `references/` |
| 完整版 | 有确定性逻辑需要执行 | `SKILL.md` + `references/` + `scripts/` |

原则：**宁可从轻量版开始，复用被证实后再升级**。不要为想象中的规模预先建目录。

## Step 3：参考扫描（可选，最多 3-5 个）

- 优先看同类高质量公开实现，学它的**模式和结构**，不抄措辞。
- 用户提供的参考次之；本地已有文件只做适配校准。
- 同时记录"不借什么"，保持新 skill 轻。
- 没有合适参考时跳过此步，不硬凑。

## Step 4：写 SKILL.md（核心交付物）

### frontmatter 先写

```yaml
---
name: <skill 名，小写连字符>
description: <一句话说清"做什么 + 什么时候用"，这是被发现和调用的关键>
---
```

description 写法：从重复任务写起，包含典型触发说法（含中文口语变体），让调用方能一眼判断该不该用它。

### 正文结构（按需裁剪，不是每个都要）

1. **目标**：一段话说清这个 skill 解决什么问题、交付什么。
2. **工作流程**：编号步骤，每步可独立执行；有判断点就写判断条件。
3. **输入输出约定**：接受什么、拒绝什么、输出什么格式。
4. **质量标准**：什么叫做好了（检查清单优于形容词）。
5. **示例**：一个完整的最小例子，胜过十段说明。
6. **常见错误**：已知的坑和规避方式（可选）。

## Step 5：补必要资产（只在值得时）

- `references/*.md`：放长内容——评分细则、检查清单、领域知识。主文件里只留链接和一句话摘要。
- `scripts/*.py`：只有**确定性、会重复执行、手写容易出错**的逻辑才值得脚本化；脚本带 `--help`。
- `examples/`：一个真实输入 → 真实输出的完整样例。
- 其余（evals、manifest、CI）在轻量/标准版一律不做，除非用户明确要团队分发。

## Step 6：自检后交付

交付前过一遍：

- [ ] 能一句话说清它干什么吗？
- [ ] description 包含典型触发说法吗？
- [ ] 输入、输出、不做的事都写明了吗？
- [ ] 步骤可独立执行、判断点有条件吗？
- [ ] 至少有一个具体示例吗？
- [ ] 主文件够瘦、细节都外移了吗？
- [ ] 没有为想象中的需求预留的空结构吗？

**交付格式**：skill 目录 + 一句能力描述 + 边界摘要（做什么/不做什么）+ 最多三个后续改进建议。
