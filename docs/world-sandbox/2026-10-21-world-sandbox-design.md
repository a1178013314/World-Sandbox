# 假如 / WHAT IF — 轻量多智能体沙盘 设计方案

> 版本：v0.1（2026-10-21）
> 原型：[prototype.html](./prototype.html) ｜ 截图：[shot.png](./shot.png)
> 参考拆解：`开源/多智能体/MiroFish`（仅借鉴机制，不复用代码）

---

## 一、要做什么

**一句话**：把一段文字（群公告、小说章节、公司通知）变成一个能自己运转的小世界——十几个有立场、有记忆、有信息盲区的角色，在群里吵起来；你可以随时丢一个变量进去，看世界怎么走。

**三个动词**：

1. **造世界**：种子文本 → 8–12 个角色卡。
2. **投炸弹**：任意轮次插入一个事件，不暂停、不重跑。
3. **审角色**：跑完后点名采访任何一个角色，它只能用自己的记忆回答。

**第四个动词（隐性但最重要）**：**让大多数人闭嘴**。每一轮角色都可以不回复——不在线、已读不回、想回没赶上，三种沉默分开记。真实群里大半时间没人说话，全员每轮发言是最大的失真来源。

**非目标（明确不做）**：

- 不做真实社交平台对接（不碰微博/小红书 API）
- 不做千级 Agent、不做 GraphRAG、不做向量库
- 不做用户系统、多租户、权限
- 不做超过 3 分钟的后台长任务
- 不追求"预测准确率"，只追求"过程可信、可解释"

### 1.1 一个内核，五种表皮

| 表皮 | 种子 | 动作语义（映射到四个原子动作） | 名场面 |
|---|---|---|---|
| 宿舍群 | 断电 / 水电费通知 | 说 / 回 / 附和 / 已读不回 | 谁在群里装死 |
| 公司群 | 组织架构调整 | 说 / 回 / 阴阳附和 / 已读不回 | 谁第一个站队 |
| 业主群 | 物业通知 | 说 / 回 / 附和 / 沉默 | 谁把事捅到隔壁群 |
| 舆论分析 | 品牌声明 / 政策通报 | 发声 / 回应 / 转发 / 沉默 | 哪句话被抓住放大 |
| 小说 / 剧本 | 章节原文 | 说话 / 反驳 / 附和 / 沉默（+ 离场） | 角色反驳作者安排 |

内核完全不变：角色 JSON、事件流、沉默门、上帝之手、采访、分叉。变的只有种子、角色卡和 prompt 里的措辞。

## 二、产品形态

一屏三栏，对应原型的三个区域：

| 区域 | 内容 | 作用 |
|---|---|---|
| 左：角色表 | 头像、身份、立场、影响力、状态（活跃/潜水/退群） | 让评委看见"人"的分布 |
| 中：群聊现场 | 分轮消息、反应数、潜水提示、退群统计 | 让涌现**看得见** |
| 右：上帝之手 | 输入"如果……"、快捷事件、分叉、世界指标、名场面、采访入口 | 让用户**能动手** |

底部固定一条「本轮涌现」：3 张卡，每张一句结论 + 可点开的原文。

**小说包不改版面，只改中栏的写法**：消息气泡换成场景流——对白、动作提示、斜体内心独白交替，底部多一个「本章」按钮，把这一场直接织成一章。左栏仍然是角色表（多了「已离场」状态），右栏仍然是作者之手（多了 `intent` 注入）。

## 三、核心概念（必须先统一）

| 概念 | 定义 | 存在哪 |
|---|---|---|
| **世界（World）** | 一次仿真的全部状态，可复制、可分叉 | 一个 SQLite 文件 |
| **角色（Agent）** | 一份私有状态：人设 + 信念 + 记忆 + 情绪 | `agents` 表，每行一个 JSON |
| **事件（Event）** | 世界上真实发生过的事，只追加、不修改 | `events` 表 |
| **信念（Belief）** | 角色**以为**发生了什么，允许错、漏、记仇 | 角色 JSON 内 |
| **交付（Delivery）** | 某条事件被哪个角色看到、什么时候 | `deliveries` 表 |
| **分叉（Fork）** | 复制某轮的世界，注入变量后独立运行 | 新 SQLite 文件 |

**最关键的一条**：

> `events` 是客观真相，`agent.belief` 是主观认知。两者的差，就是仿真好看的原因。
> 例：第 2 轮陈经理确实贴了明细，但王阿姨那轮没被激活、没看到；第 3 轮她仍然说"先把账贴出来"。这不是 bug，是人。

**角色不是常驻进程**：每次被唤醒时加载自己的 JSON，渲染成 prompt，输出一个动作，再写回去。LLM 调用之间无状态。

## 四、状态模型

### 4.1 存储选择

**每个世界一个 SQLite 文件**：`worlds/<world_id>.sqlite`

理由：
- 分叉 = 复制一个文件，最直观；
- 查询方便（UI 列表、按轮次取事件）；
- 每行一个 JSON 列，既保留"每个角色一套 JSON"的心智模型，又可索引；
- 不引入 Postgres/Redis/文件数据库混用。

### 4.2 表结构

```sql
CREATE TABLE world (
  id            TEXT PRIMARY KEY,
  parent_id     TEXT,              -- 分叉来源
  fork_round    INTEGER,           -- 从第几轮分出
  seed_json     TEXT NOT NULL,     -- 种子、场景、配置
  current_round INTEGER DEFAULT 0,
  status        TEXT DEFAULT 'ready',  -- ready | running | paused | done
  created_at    TEXT
);

CREATE TABLE agents (
  world_id      TEXT NOT NULL,
  agent_id      TEXT NOT NULL,
  profile_json  TEXT NOT NULL,     -- 不变：身份、目标、恐惧、口吻、立场
  belief_json   TEXT NOT NULL,     -- 会变：已知/未知、关系、情绪
  memory_json   TEXT NOT NULL,     -- 会变：最近事件引用 + 摘要
  state_json    TEXT NOT NULL,     -- 会变：活跃度、沉默轮数、上次发言
  PRIMARY KEY (world_id, agent_id)
);

CREATE TABLE events (
  seq           INTEGER PRIMARY KEY AUTOINCREMENT,
  world_id      TEXT NOT NULL,
  round         INTEGER NOT NULL,
  kind          TEXT NOT NULL,     -- post | reply | like | ignore | system | intervention | exit | author_rejected
  actor_id      TEXT,              -- system/intervention 为空
  target_id     TEXT,              -- reply/like 的目标
  content       TEXT,
  payload_json  TEXT,              -- 情绪、理由、元数据
  visibility    TEXT DEFAULT 'public',
  created_at    TEXT
);

CREATE TABLE deliveries (
  world_id      TEXT NOT NULL,
  event_seq     INTEGER NOT NULL,
  agent_id      TEXT NOT NULL,
  seen_round    INTEGER NOT NULL,
  salience      REAL DEFAULT 0.5,
  PRIMARY KEY (world_id, event_seq, agent_id)
);

CREATE TABLE calls (               -- 成本与调试，不参与业务
  id            TEXT PRIMARY KEY,
  world_id      TEXT,
  round         INTEGER,
  agent_id      TEXT,
  prompt_hash   TEXT,
  tokens_in     INTEGER,
  tokens_out    INTEGER,
  latency_ms    INTEGER,
  raw_response  TEXT,
  ok            INTEGER
);

CREATE TABLE rounds (              -- 每轮在场/开口/沉默快照，回放必需
  world_id      TEXT NOT NULL,
  round         INTEGER NOT NULL,
  time_label    TEXT,              -- 09:00 / 21:00
  active_ids    TEXT,              -- 本轮在线（看到了消息）
  spoke_ids     TEXT,              -- 真正开口的
  silent_ids    TEXT,              -- 在线但选择沉默的
  metrics_json  TEXT,
  PRIMARY KEY (world_id, round)
);
```

### 4.3 角色 JSON（逻辑视图）

```json
{
  "id": "wang_ayi",
  "profile": {
    "name": "王阿姨",
    "role": "退休 · 12 年业主",
    "goals": ["阻止涨价", "别被说成闹事"],
    "fears": ["被邻居觉得小题大做"],
    "voice": "短句、爱反问，口头禅「先把账贴出来」",
    "stance": { "issue": "物业费涨价", "position": "oppose", "intensity": 0.9 },
    "influence": 0.86,
    "activity": { "level": 0.8, "hours": [7, 8, 9, 19, 20, 21] },
    "can_see": ["本群消息", "被点名", "5 栋群转述"]
  },
  "belief": {
    "known": [
      { "fact": "物业宣布涨到 3.8", "ref": 1 },
      { "fact": "电梯坏了三天", "ref": 3 }
    ],
    "unknown": ["陈经理后来贴过明细"],
    "relations": { "chen_jingli": -0.7, "chen_lvshi": 0.4 },
    "summary": "他们在回避账目问题，我得把事闹大一点"
  },
  "memory": {
    "summary": "我认为涨价不合理，陈经理在打太极。",
    "recent": [
      { "round": 1, "kind": "saw", "ref": 1, "gist": "物业宣布涨价", "salience": 0.9 },
      { "round": 1, "kind": "said", "ref": 4, "gist": "要求先贴账", "salience": 0.8 }
    ]
  },
  "state": {
    "mood": { "label": "愤怒", "intensity": 0.8 },
    "last_spoke_round": 1,
    "silent_rounds": 0,
    "actions_total": 2
  }
}
```

**字段约束**：

- `profile` 生成后不再改（保证角色一致性）。
- `memory.recent` 最多 20 条，只存 `ref + gist`，**不存全文**。
- `belief.unknown` 是刻意保留的：它是"误解"和"谣言"的燃料。
- 角色 JSON 里**不放**模型名、API key、系统配置。

## 五、一轮是怎么跑的

### 5.1 主循环

```ts
for (let r = world.current_round + 1; r <= totalRounds; r++) {
  const active = schedule(world.agents, r);           // 30%–40%
  const feed = rankFeed(world, active, r);            // 每个角色取 top 8
  const speakers = active.filter(a =>
    passGate(a, feed[a.id], r)                        // 5.6 规则门：不通过就不发请求
  );
  const acts = await Promise.all(
    speakers.map(a => act(a, feed[a.id], r))          // 只有通过规则门的才调用 LLM
  );
  applyAndDeliver(world, active, acts, r);            // 写 events + deliveries + 沉默快照
  updateMemory(world, active, r);                     // 追加记忆、重算情绪
  if (r % 4 === 0) compactMemory(world, active);      // 压缩摘要
  snapshot(world, r);                                 // 可选：导出 JSON
  world.current_round = r;
}
```

> 注意 `applyAndDeliver` 传的是 `active` 而不是 `speakers`：沉默的人也要进入本轮快照，否则回放里看不出"谁在场却没说话"。


### 5.2 排班

- 每轮激活比例：`30%–40%`，上限 6 人。
- 个体概率：`activity.level`（0–1）。
- `round` 映射一个模拟时段（如 09:00 / 14:00 / 21:00 / 次日 08:00）；`activity.hours` 不包含该时段的角色，直接不参与本轮抽签，深夜轮次自然安静。
- 同一个角色连续 2 轮发言后，概率减半（防刷屏）。
- 被点名、被回复的角色，下一轮**强制上线**——只保证看到，不保证发言（见 5.6）。
- 不生成任何"不参与计算"的配置字段——这是对 MiroFish 那条教训的直接修正。

### 5.3 Feed 排序（必须是真函数）

```ts
score =
  0.40 * recency(event, r)        // 越新越高
+ 0.22 * heat(event)              // 点赞/回复数归一化
+ 0.18 * relevance(agent, event)  // 关键词重叠 + 立场相反加权
+ 0.08 * influence(author)
+ 0.12 * random();                // 探索噪声，防止所有人看同样 3 条
```

取 top 8 渲染进 prompt。`random()` 用固定种子，保证回放一致。

### 5.4 动作 schema

```json
{
  "action": "post | reply | like | ignore",
  "target_id": "post_12",
  "text": "涨 35%？先把账贴出来。",
  "emotion": { "label": "愤怒", "intensity": 0.8 },
  "private_reason": "我要在群里立住‘替大家说话’的人设"
}
```

规则：

- 每轮只能 1 个动作；`ignore` 不需要 text。
- `post` ≤ 80 字，`reply` ≤ 40 字（群聊语感）。
- `private_reason` **不给其他角色看**，用于调试与生成角色内心状态摘要。
- 选 `ignore` 时也建议填 `private_reason`——"我为什么不说"比"我说了什么"更适合做采访和名场面卡。
- Zod 校验；失败自动修一次；再失败降级为 `ignore`（不让一轮崩掉）。
- 每个角色 4 轮内最多 2 次主动 `post`，其余必须 `reply/like/ignore`。

### 5.5 应用动作

1. 写 `events`（`kind=post/reply/like`）；`ignore` 不写事件，只更新 `state.silent_rounds`。
2. 计算 `deliveries`：
   - `post`：本轮所有激活角色可见；
   - `reply`：被回复者、被点名者、发帖者可见；
   - `like`：仅目标作者可见（"谁给我点了赞"）；
   - `ignore`：不产生事件，只更新 `state.silent_rounds`。
3. 本轮**未被激活**的角色：不产生 delivery → 之后可能"不知道这件事"，形成信息差。
4. 更新行动者记忆 + 情绪（规则：被反对 → 强度 +0.1；被附和 → +0.05，上限 1）。
5. 把本轮 `active_ids / spoke_ids / silent_ids` 写进 `rounds` 表，保证回放能复现"谁在线但没说话"。
   `silent_ids = active_ids - spoke_ids`，包含两类人：被规则门拦下的、模型自己返回 `ignore` 的。两者在 `calls` 表里可区分（一个没记录，一个 `ok=1`）。

### 5.6 沉默门：不是每一轮都必须说话

**默认允许不回复**，而且"不说话"有三种，必须分开记：

| 类型 | 原因 | 记在哪 | 事后表现 |
|---|---|---|---|
| 不在线 | 没被抽中 / 不在作息时段 | `rounds.active_ids` 不含 | 采访说"我那会儿没看手机" |
| 已读不回 | 在线，看完选择沉默 | `rounds.silent_ids` | 群里没消息，但记忆更新了 |
| 想回没赶上 | 生成失败 / 被限流 | `calls.ok = 0` | 下一轮可补一句"刚看到" |

**两级决策，先规则后模型**：

1. **规则门（不花钱）**：先算 `p_speak`，不通过就直接静默，**不调用 LLM**。

```
p_speak = activity.level
        × gateCoefficient                        // 场景系数：宿舍 0.75 / 公司 0.70 / 舆论 1.20 / 业主群 1.00 / 小说 1.05
        × (1 - min(silent_rounds, 3) × 0.1)      // 越沉默越难开口
        × context_multiplier

context_multiplier:
  被点名 / 被回复       1.8
  话题与自身利益相关     1.4
  连续 2 轮已发言        0.5
  潜水 ≥ 3 轮            1.2
最终 clamp 到 [0.05, 0.95]
```

2. **模型门（花钱）**：通过规则门的角色才调用一次；模型仍可选 `ignore`，用来保留"看了但懒得说"的不可预测性。

**保底规则**：

- 每轮至少 2 人开口，不足时从"被点名 / 高活跃"里补 1–2 人（在场者中重取 `p_speak` 最高的）。补进来的人照常走模型门，仍可自己选 `ignore`。**保底只影响"谁被问"，不影响"必须说什么"。**
- 有人被 @ 时，至少 1 个被 @ 的人开口；但不保证是本人，可能装死让别人替他说。
- 连续 3 轮无人回应的话题自动降温（feed 权重减半）。

**为什么这么做**：

- 真实群里大多数人是"已读不回"，全员每轮发言是最大的失真来源。
- 沉默门把调用量砍掉约 1/3，成本和延迟一起降。
- "谁不说话"本身就是素材：`李工 已读 14 条，未发言`。

## 六、记忆、视野与压缩

### 6.1 三层

| 层 | 内容 | 更新频率 |
|---|---|---|
| 角色卡 | 身份、目标、恐惧、口吻、立场 | 永不变 |
| 信念 | 已知事实、未知事实、关系冷暖、当前 summary | 每轮 |
| 情景记忆 | 最近 20 条事件引用 + 摘要 | 每轮追加，每 4 轮压缩 |

### 6.2 可见性规则（差异化核心）

```ts
function canDeliver(agent, event, round) {
  if (event.kind === 'intervention' && event.payload.to === 'all') return true;
  if (event.kind === 'intervention' && event.payload.to !== agent.id) return false;
  if (event.actor_id === agent.id) return true;
  if (event.kind === 'reply') return event.target_id === agent.id || event.payload.mentions?.includes(agent.id);
  return agent.activeInRound(round);   // 群消息只给在线的人
}
```

- 不在线 → 不投递 → 进 `belief.unknown`。
- 被转述 → 以"听说"进入 `known`，标注 `source: 'hearsay'`。
- 采访中问到不知道的事，角色必须回答"我那会儿没看手机"——**允许不知道**。

### 6.3 压缩

每 4 轮一次，单次调用：

> 把以下 20 条记忆压成 200 字以内，保留：谁欠我、谁支持我、我立过什么 flag、我还没搞清的事。不要编造。

压缩结果写回 `memory.summary`，原文保留在 `events`，可随时回溯。

## 七、三个差异化功能

### 7.1 上帝之手（真实注入）

- 接口：`POST /api/worlds/:id/events`
- 入参：`{ content, visibility: "all" | agentId, effectiveRound, mode? }`
- 写入 `events.kind = 'intervention'`，下一轮开始时生效。
- **不暂停、不重启**；如果世界正在跑，事件排队到下一轮。
- 与 MiroFish 的差别：它的 `scheduled_events` 恒为空，运行中注入不了；我们把它做成真功能。

两种注入，其他场景默认 `fact`：

| mode | 写什么 | 角色能不能抵抗 | 用在 |
|---|---|---|---|
| `fact` | 直接写进 `events`，在场者必然看到 | 不能，只能反应 | 停水、名单泄露、第二份遗嘱 |
| `intent` | 不能写进 `events`，只作为 `author_note` 进入相关角色的 prompt | 能：可以顺、可以歪、可以直接否决 | “她当场答应了”“母亲开口了” |

`intent` 被否决时记 `events.kind = 'author_rejected'`，前端打一个「角色否决了作者」的标记——这是小说场景最值得演的一秒。这里的差别不只是参数，而是世界观：**群聊场景里上帝之手给的是事实，小说场景里作者给的只是意图**。

### 7.2 分叉 A/B（真实双世界）

- 接口：`POST /api/worlds/:id/fork`，入参 `{ atRound, intervention? }`
- 实现：复制 `worlds/<id>.sqlite` → 新 id；`current_round = atRound - 1`；写入分叉事件；独立跑 N 轮。
- 对比页：只对比 4 个指标 + 3 条名场面，不做长报告。
- 成本控制：同一 `prompt_hash` 命中缓存则直接返回；两个世界只有变量那一步不同。

### 7.3 采访（带信息边界）

- 接口：`POST /api/worlds/:id/interview`，入参 `{ agentId, question }`
- Prompt = 角色卡 + belief + memory + 最近 10 条本人可见事件；**不注入全局事件**。
- 输出 2–4 句，保持口吻；不知道就说不确定。
- 返回附带 `cited: [eventSeq]`，前端可点开原话，证明不是瞎编。

## 八、Prompt 结构

### 8.1 角色行动（每轮）

```
[system]
你是「王阿姨」，退休 12 年的业主。你只根据下面的事实和记忆行动。
不要跳出角色，不要总结，不要解释规则。
只输出 JSON，不要 markdown。

[角色卡]  姓名/身份/目标/恐惧/口吻/立场/影响力
[信念]    已知事实（带 ref）/ 未知 / 对几个人的关系冷暖 / 当前 summary
[记忆]    最近 12 条 + 摘要
[本轮看到的消息]  按 feed 顺序，带作者、时间、反应数
[可选]    场景：地点、时间、在场者 / 已离场者（小说包）
[可选]    本轮发生的新事件（上帝之手 fact）
[可选]    作者意图（intent）：作者希望……，你可以顺从、扭曲或拒绝
[可选]    文风：书面叙述，对白 ≤ 40 字，不写剧本格式（小说包）
[动作约束] 动作类型、字数、每 4 轮最多 2 次 post
[输出 schema]
```

### 8.2 采访

```
[system] 你仍然是「王阿姨」，正在被单独问话。只用你经历过的事回答，不知道就说不知道。
[角色卡 + 信念 + 记忆]
[你的发言记录（只含本人可见）]
[问题] ...
[要求] 2–4 句，保持口吻，不复述设定。
```

## 九、指标与"预测"（诚实定义）

| 指标 | 计算 | 展示 |
|---|---|---|
| 情绪温度 | 影响力加权平均情绪强度 × 100 | 68 / 100 |
| 极化度 | 立场分布的归一化熵取反 | 0–1 |
| 沉默率 | 拆两个：离线率（未激活/总数）、已读不回率（在线但沉默/在线） | 41% = 18% + 23% |
| 传播速度 | 跨群转发 + 引用 / 本轮发帖数 | 2.4× |
| 升级指数 | `0.4×反对占比 + 0.3×跨群扩散 + 0.3×平均强度` | 0–100 |
| 张力曲线 | 每轮 `(反驳 + 质问) / 本轮发言数`，再做 3 轮滑动平均 | 折线 |
| 秘密暴露顺序 | 标记为 `secret` 的事实首次进入公开事件的轮次 | 列表：谁先知道 |
| 离场人数 | 累计 `events.kind='exit'` | 2 人 |

小说包只看后三个，**不展示任何概率**——那一屏的结论是"哪一版更好看"，这本来就是作者的判断。

**不要展示"62% 概率"这种伪精度**。原型里的数字是示意；实现时二选一：

1. **MVP**：只展示「升级指数 + 趋势箭头」，并注明"启发式"。
2. **进阶**：从当前轮做 3 次短续跑（各 2 轮），用"出现联名投诉"的频率当概率，标注样本数。

## 十、技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 编排 | **裸循环 + Promise.all** | 无工具、无 handoff、无协作；LangGraph 的图抽象不匹配（详见 §10.1） |
| 语言/框架 | TypeScript + Next.js 15 | 原型是 HTML，迁移成本最低；你熟 |
| 存储 | SQLite（`better-sqlite3`）+ `drizzle-orm` | 单文件、可分叉、可查询 |
| 校验 | Zod | 动作 schema、一次修复、失败降级 |
| 模型（跑轮） | qwen-flash / qwen-plus（DashScope 兼容） | 快、便宜、JSON 稳定 |
| 模型（造人/名场面） | qwen-plus 或 deepseek-chat | 质量优先，调用量小 |
| 并发 | `p-limit(5)` | 防 429；单轮 6 人足够 |
| 流式 | SSE 推「轮次事件」 | 不逐 token 推 10 个角色 |
| 可观测 | `calls` 表 + `/debug` 页 | 每次调用的 prompt_hash/耗时/token 可查 |
| 部署 | 单容器 + 一个 volume | 不引入 Redis/队列 |

### 10.1 为什么不用 LangGraph / OASIS / Zep

- **LangGraph**：它解决"状态机 + 断点 + 人工介入"；我们的循环就是一个 for，分叉靠复制文件。用了它，本质是把 for 换成图，收益不抵抽象成本。只在"报告 Agent 的多工具循环"里可选。
- **OASIS/CAMEL**：平台锁死 Twitter/Reddit，参数黑盒，正是 MiroFish 的问题。
- **Zep**：10 个角色、8 轮，用不上图谱；"世界记忆"用 `events` 表 + 关键词检索足够。

POST   /api/worlds/:id/step          跑一轮
POST   /api/worlds/:id/run           连续跑到结束（后台）
GET    /api/worlds/:id/stream        SSE：round / event / metric

## 十二、成本与预算

单次默认跑（12 角色 × 8 轮 × 35% 激活）：

| 项 | 次数 | 说明 |
|---|---|---|
| 角色行动 | ≈ 24 | 激活约 34 人，沉默门后约 70% 真正开口 |
| 角色生成 | 12 | 可复用模板 + 微调 |
| 记忆压缩 | 4 | 每 4 轮一次，只压活跃角色 |
| 名场面卡 | 3 | 每轮或整局一次 |
| 采访 | 1–3 | 演示时手动触发 |
| **合计** | **≈ 45 次/世界** | 上限 55；A/B 双世界 ≈ 90 次 |

预算闸门：

- 单次调用 `max_tokens=300`（行动）/ `800`（造人）。
- 单世界调用上限 120 次，超限停止并提示。
- `prompt_hash` 缓存：回放/分叉命中即不花钱。
- 演示只跑 6 轮，剩余轮次用缓存回放。

## 十三、风险与兜底

| 风险 | 表现 | 兜底 |
|---|---|---|
| 模型输出不合 JSON | 一轮崩 | Zod 校验 + 1 次修复 + 降级 `ignore` |
| 角色同质化 | 人人讲道理 | `voice` + 极端利益 + 立场相反者在 feed 里加权 |
| 刷屏 | 每轮都是同几个人 | 活跃度衰减 + 4 轮内最多 2 次 post + `ignore` |
| 成本超限 | 账单失控 | 调用上限 + 轮次上限 + 缓存 |
| 现场延迟 | 跑一轮要 20s | 预跑缓存 + SSE + 只跑 3 轮现场 |
| 演示翻车 | 网络/模型 429 | 本地预置 2 个世界，直接回放 |
| 版权/合规 | 参考了 AGPL 代码 | 只借鉴机制，不复制代码；文档留痕 |

| 时间 | 任务 | 产出 |

| H10–H14 | 上帝之手 + SSE + 指标 | 能中途注入 |
| H14–H18 | 采访 + 名场面卡 | 三个动词闭环 |
| H18–H22 | 分叉 + A/B 对比页 | 差异化完成 |

小说包的三处差异（离场 / 内心独白 / `intent` 否决）合计约 60 行，建议和分叉一起放在 H18–H22：两者都在渲染层，不碰主循环，改坏了也不影响主路径。

## 十五、验收标准

- [ ] 12 个角色、8 轮，单次跑完 ≤ 90 秒，调用 ≤ 120 次。
- [ ] 每条消息可追溯到 `agent_id + round + 调用日志`。
- [ ] 同一个世界回放两次，消息逐字一致（固定 seed + 缓存）。
- [ ] 在第 3 轮注入「停水 6 小时」，第 4 轮至少 2 个角色作出反应。
- [ ] 分叉世界与原世界在前 3 轮完全一致，第 4 轮开始分道。
- [ ] 采访一个"当时不在线"的角色，它明确说"我不知道"。
- [ ] 至少出现 2 次"在线但选择沉默"，且 `rounds.silent_ids` 可查。
- [ ] 宿舍 / 公司 / 舆论 / 小说四个种子包都能一键创建，各跑通 3 轮。
- [ ] 小说包至少出现 1 次「角色否决了作者」（`author_rejected`），且同一轮有 1 条内心独白被渲染。
- [ ] 断网情况下能回放预置世界（演示兜底）。

## 附录 D：四个附加种子包（宿舍 / 公司 / 舆论 / 小说）

**看什么**：谁第一个站队、谁装没看见、谁把截图传出去。
**推荐注入**：第 3 轮投放「HR 误发了一份名单截图」。
**关键指标**：极化度、已读不回率、升级指数。

### D3 舆论分析（10 人）

```text
【某饮品品牌声明】
近日有消费者反映饮用后出现不适。经初步核查，相关批次检测结果符合国家标准。
我们已第一时间下架该批次产品，并配合监管部门调查。
对恶意造谣者，保留追究法律责任的权利。
—— 品牌公关部
```

| 角色 | 目标 | 口吻 | 默认立场 |
|---|---|---|---|
| 品牌公关 | 止血 | 官方、克制 | 维护品牌 |
| 当事人消费者 | 要说法 | 具体、带情绪 | 追责 |
| 围观路人 | 吃瓜 | 短句、玩梗 | 摇摆 |
| 母婴博主 | 涨粉 / 避雷 | 强情绪、带标签 | 质疑 |
| 财经媒体 | 抢首发 | 引用数据、克制 | 中性偏质疑 |
| 竞品公关 | 借势 | 不点名、暗示 | 暗中拱火 |
| 平台运营 | 控风险 | 规则导向 | 中立 |
| 律师 | 讲责任边界 | 法条、条件句 | 中立 |
| 监管账号 | 回应关切 | 通报体 | 官方 |
| 营销号 | 流量 | 标题党、夸张 | 煽动 |

**看什么**：哪句话被抓住放大（「恶意造谣」通常最容易被截）、是否出现二次危机、媒体框架怎么定。
**推荐 A/B**：A 保持强硬声明，B 追加道歉 + 赔付方案，各跑 5 轮对比升级指数。
**关键指标**：情绪温度、传播速度、极化度。

> 注意：这里做的是「回应策略预演」，不是「真实舆情预测」。对外话术统一为「给每种回应一次彩排」，避免被质疑准确率。

### D4 小说 / 剧本（8 人，一场戏）

```text
【《分家》第三节 · 老宅客厅】
律师合上文件夹：「遗嘱只有一条——老宅归小女儿。」
长兄把茶杯轻轻搁下：「她才二十四，连房贷是什么都不知道。」
二姐没抬头，指甲在桌面上划了一下：「我在医院守了十一个月。」
母亲坐在最里面的藤椅上，一直看着窗外，没说话。
```

| 角色 | 目标 | 口吻 | 默认立场 |
|---|---|---|---|
| 长兄 | 拿回老宅抵债 | 低声讲理，忽然拔高 | 反对遗嘱 |
| 二姐 | 要一句「这些年辛苦你了」 | 报数字、克制 | 反对遗嘱 / 要补偿 |
| 三弟 | 谁都不得罪，等母亲开口 | 打岔、插科打诨 | 摇摆 |
| 小妹（受益人） | 想走，不想欠这个家 | 短句、少解释 | 想放弃 |
| 大嫂 | 把丈夫推到前面 | 客气，句句带刺 | 反对 |
| 律师 | 把程序走完 | 术语、无情绪 | 中立 |
| 母亲 | 守住一个秘密 | 几乎不说话 | 沉默（关键） |
| 邻居（旁听） | 看热闹，回头传话 | 感叹、插一句 | 围观 |

**看什么**：谁先撕破脸、谁一直没说话、谁先离场。
**推荐注入**：第 3 轮 `fact`「律师：还有第二份遗嘱」；第 4 轮 `intent`「母亲放下茶杯，说了第一句话」——她完全可能不听你的。
**推荐 A/B**：A 小妹当场拒绝继承 / B 小妹沉默签字，各跑 6 轮，比对张力曲线与「秘密暴露顺序」。
**关键指标**：张力曲线（每轮反驳 + 质问占比）、秘密暴露顺序、离场人数。

**和群聊场景只差三处**（`intent` 注入已在 §7.1 统一处理，不重复算）：

| 差异 | 群聊场景 | 小说场景 | 实现 |
|---|---|---|---|
| 舞台 | 群，消息可回看 | 一场戏，同一时间同一地点 | 角色卡加 `stage`，UI 换成对白 + 动作提示 |
| 离场 | 退群 | 摔门出去 / 被叫走 | 规则触发，写 `events.kind='exit'`；`presence=out` 后不收 delivery，被点名或注入才回来 |
| 沉默 | 什么都不显示 | 内心独白（斜体） | `ignore.private_reason` 直接渲染成心理描写 |

**产物不是报告，是一章**：跑完把 `events` 按轮次织成 600–800 字推演章节（一次调用），外加 3 张名场面卡。别的场景交付“分析”，这个场景交付“可读的一段小说”——演示时这一屏比任何指标都好使。

**对外话术**：不是“预测结局”，是“给作者的第二稿”。和舆论场那句“给每种回应一次彩排”是同一套防御。

### D5 五个包的参数对照

| 场景 | 角色数 | 推荐轮次 | 种子长度 | 首发动作 | 沉默基线（预期） | 主看指标 |
|---|---|---|---|---|---|---|
| 宿舍群 | 6 | 6 | 80 字 | 舍长发通知 | 55%–65% | 已读不回率、结盟 |
| 公司群 | 8 | 8 | 100 字 | HRBP 发通知 | 60%–70% | 极化度、站队速度 |
| 舆论分析 | 10 | 5 | 120 字 | 品牌声明 | 35%–45% | 传播速度、情绪温度 |
| 小说 / 剧本 | 8 | 6 | 120 字 | 律师宣读遗嘱 | 30%–40% | 张力曲线、秘密暴露顺序 |
| 业主群（默认） | 12 | 8 | 100 字 | 物业通知 | 40%–50% | 升级指数、跨群扩散 |

**沉默基线为什么这么设**：场越小、彼此越熟、后果越直接，人越倾向“当面说”或干脆装死——所以宿舍、公司最高。舆论场是公开表演，说话有观众收益，表达欲反而最强。小说场居中：对白密集，但沉默会被写成心理描写，所以“不说”也有产出。

调参方式：把 `p_speak` 的 `activity.level` 整体乘一个场景系数（宿舍 0.75 / 公司 0.7 / 舆论 1.2 / 业主群 1.0 / 小说 1.05），比逐个人改角色表省事，也保证五个场景共用一套规则门。
